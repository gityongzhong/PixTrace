## 免费去背景工具 · 技术方案（讨论阶段，未编码）

用户提出「能否开发一个免费去背景的软件」。经四问确认需求边界：

- 形态：Windows 桌面端（PySide6 + PyInstaller）
- 模型：双档可切换（极速 u2netp / 高精 isnet-general-use）
- 用途：**开源发布** → 全链路许可必须宽松（MIT / Apache-2.0），禁用 CC BY-NC
- 功能：批量处理 + 背景替换；**不做** alpha matting、**不做** GPU 加速（列为后续扩展）

关键技术决策（已写入方案文档）：

1. 推理走 `onnxruntime`（MIT），**刻意不用 PyTorch**（打包 1.5GB+）与 `rembg` 运行时（依赖链冗余），仅借用模型文件思路，预处理/后处理自研。
2. **刻意不用 OpenCV**，统一 Pillow + numpy，规避 wheel 内置 FFmpeg 的 LGPL 杂音。
3. 模型仅取官方仓库（U^2-Net / DIS，均 Apache-2.0），**排除 BRIA RMBG-1.4/2.0（CC BY-NC，禁商用）**；ONNX 由自研 `scripts/export_onnx.py` 从官方权重导出，附 commit + sha256。
4. 并发用 ProcessPoolExecutor（每进程 1 session、intra_op=1），而非线程池，避免 ONNX 内部线程与文件级并发抢核。
5. 打包 `onedir`（非 onefile），便于 PySide6 的 LGPL 合规与模型外挂。
6. 模型分发：安装包带极速档，高精档按需下载，另提供「手动导入」离线兜底。

产出：`去背景工具-技术方案.md`（含 14 节，含待定项 A-D 与风险表）。

下一步：等用户评审方案，确认待定项后再进入 M1（核心引擎）。

## M1 + M2 完成实测（同日晚）

用户拍板「先只做 M1 + M2」。当日完成核心引擎、单图 CLI、批量调度、背景替换，全部验证通过。

### 关键实测结论（已固化进代码）

1. **isnet 与 u2net 预处理常数不同**：u2netp 用 ImageNet (0.485,0.456,0.406)/(0.229,0.224,0.225)；
   isnet-general-use 用 (0.5,0.5,0.5)/(1.0,1.0,1.0)。我凭「U-2-Net 家族都是 ImageNet」的记忆推广，
   导致 isnet 输出全零垃圾，靠对照实验 + 拉 rembg 源码 diff 定位。教训：**模型预处理必须逐模型
   核对官方脚本，严禁凭家族经验推广**。
2. **letterbox 优于直接拉伸**（对照实验：3840×2400 强行拉伸时球体遮罩出现水平切边伪影）。
3. **大/小模型最优并发策略相反**（12 核实测）：u2netp 单图 250ms，批量用 6 进程×intra=1；
   isnet 单图 1.2s，intra=1 会劣化到 7.2s（慢 6 倍），必须 1 进程×默认线程。已固化为
   `ModelSpec.worker_intra`。
4. div_max 与 div255 归一化在 8bit 图上等价（像素最大值即 255），取 div255。
5. Read 工具能直接查看生成的图片/遮罩——「生成对比图 + 自己读图」是验证视觉任务的有效闭环。

## M3 GUI 完成（同日深夜）

用户确认做 M3。当轮完成 PySide6 界面并全部验证。

### 界面组成（app/ui/）

- `main_window.py`：主窗口（菜单/工具栏/任务树/参数面板/进度/状态栏、拖拽、QSettings 持久化）
- `settings_panel.py`：参数面板（含格式-背景联动：JPEG 自动禁用透明）
- `preview.py`：原图-结果对比预览（可拖分割线，透明区棋盘格渲染）
- `controller.py`：BatchController，threading.Thread 包 run_batch + Qt 信号回传
- `style.py`：暗色 QSS（写成 Python 常量，避免打包时资源路径问题）
- 列表刻意不做缩略图（大列表会卡 UI），缩略放到双击预览

### 关键决策与坑

1. **pip 装 PySide6 走默认源 10 分钟下不完 80MB**，换阿里源 pip 也只有 1.4MB/9min；
   最终用本机已有的 **uv**（`C:/Users/Administrator/.local/bin/uv.exe`）1 分 17 秒装完。
   以后装大包直接用 uv（`uv pip install --python <venv> --index-url 阿里源`）。
2. **GUI 必须真实批处理冒烟测试**：截图只能验证布局，第一轮冒烟就抓到 bug——
   子进程返回的 Task 只更新了列表行，没写回 self._tasks，导致「重跑失败项」/状态筛选
   基于过期 pending 状态会失效。已修（_task_map + _sync_task）。
3. **app/main.py 的 PySide6 import 放在 main() 函数内**：Windows spawn 的子进程会重新
   导入 __main__，推迟 import 让每个 worker 少加载一次 Qt。
4. 截图自检工作流：scripts/shot_gui.py 渲染窗口→grab()→保存 PNG→用读图工具自检，
   无人值守可迭代界面。scripts/smoke_gui.py 做真实批处理冒烟（含超时保护）。
5. 清华源连 PySide6 包都找不到（同步不全），阿里源可用。

### 验证结果

- 空状态/加载态/预览窗/批处理完成态 4 张截图均正常（.shots/）
- GUI 真实批处理：3 张壁纸全部完成，平均 985ms/张，与 CLI 基准一致
- 参数持久化、取消、失败重跑的逻辑均已接通（冒烟覆盖主链路）

### 交付物（dist/）

| 产物 | 大小 | 说明 |
|---|---|---|
| `nobg-0.1.0-portable.zip` | 228 MB | **免安装便携版（主交付物）**，两档模型全内置，解压即用 |

### 新增代码

- `app/infra/paths.py`：路径中枢（is_frozen / app_dir / resource_dir / is_portable / is_writable）
- `app/infra/downloader.py`：模型下载（标准库 urllib，Range 续传 + sha256 + 3 次重试 + 取消 +
  原子落盘 .part→正式文件 + sources.json 镜像配置）
- `app/ui/model_dialog.py`：模型管理对话框（状态/下载/手动导入——文件名匹配不上时按 sha256 反查档位）
- `scripts/build.py`（一键构建）、`build/nobg.spec`、`build/installer.iss`、`scripts/make_icon.py`（代码生成图标）
- **便携模式**：exe 旁有 `portable.txt` 标记时，模型与日志写程序目录，不写 APPDATA/注册表；
  目录只读时自动回退 APPDATA

### 关键验证（全部真实 exe，不靠推断）

1. **冻结版多进程批处理通过**：`nobg.exe --selftest` 覆盖模型定位→合成素材→批处理→alpha 校验；
   freeze_support() 必须放在 `__main__` 最外层，否则每个 worker 会重启整个 GUI。
2. **便携版从 zip 解压后复测**：两档模型均在程序目录内找到并跑通（fast 3张/2进程，quality 1张/1进程），
   数据只落在便携目录（models/ 与 logs/），模拟用户真实拿到包的场景。
3. 冻结版 GUI 启动正常（存活 7s，167MB 内存）。
4. 下载器实测：4,574,861 字节、sha256 一致、断点续传从 1000 字节起点成功、无 .part 残留（本机走代理 28KB/s）。

### 坑与教训

1. **本环境有批量删除保护**（>100 文件需确认）：PyInstaller 重建前清空 dist/ 会被拦截导致构建失败，
   需先手动 `rm -rf dist/nobg dist/nobg-<版本>-portable`（权限提升已获准）。用户本机构建无此问题。
2. **bash 里嵌套双引号会拆参数**：`"/O$(cygpath -w "$PWD/dist")"` 遇空格路径断成两个参数，
   ISCC 报 "more than one script filename"。应走 build.py（子进程列表传参）。
3. **PowerShell 工具的 stdout 偶尔不回传**——需要读输出时改用 bash。
4. 自检必须覆盖**全部分发内容**：最初只测极速档，便携版带了两档模型，
   「自检范围 < 分发范围」会漏掉高精档在冻结环境的问题。已改为双档都测。
5. 安装向导维持 Inno 默认英文：第三方中文 .isl 可含可执行 [Code] 段，未经审计不进构建链
   （jrsoftware 官方 Unofficial 目录里也没有简体中文）。
