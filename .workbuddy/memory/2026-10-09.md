## v0.4.0 三处高频动画（用户问「可不可以用 CSS 做动画」引出）

- 结论：QSS 只是 CSS2.1 子集，不支持 transition/animation/@keyframes/transform，
  伪状态全是瞬时硬切。过渡只能用 Qt 动画框架算中间值。
- 用户选「只做三处高频」：进度条平滑、状态文字淡入、拖拽框颜色过渡。
- 新增 app/ui/anim.py：TintAnimation（0→1 过渡进度驱动自绘插值）、
  ValueRoller（int 属性滚动，QPropertyAnimation on b"value"，roll_to/snap）、
  mix() 颜色插值、paint_tint_frame()（自绘底色+1px 边框+顶部高光）、fade_in()。
  docstring 写死三条规矩：不逐帧改 QSS（每帧全量重算样式会掉帧）、
  一控件一 effect（阴影与透明度互斥）、动画短且只在状态变化瞬间播。
- main_window：_set_status 淡入 150ms（起始 opacity 0.45 不给 0，进度回调每秒
  重播好几次，全透明会闪；文字相同不重播）；_on_progress 用 ValueRoller.roll_to，
  _on_finished/_on_failed 用 snap（完成时必须停表，否则进度条在「已完成」下慢慢爬）；
  start() 重置进度 snap(0)。
- dropzone.DropArea 与 main_window.DropBar：set_active 改 TintAnimation 驱动，
  paintEvent 用 paint_tint_frame 自绘且**不调 super().paintEvent()**（否则 QSS 背景叠加）。
  style.py 删掉 dropbar/droparea 的 background/border 声明（两套颜色定义会打架）。
- QRect.adjusted 只吃 int，传 0.5 截断成 0——内缩半像素必须 QRectF。
- shot_gui.py 加 settle()（QEventLoop 等 320ms，否则截到动画中间态）+ hover 场景。
